=== Summary of the fix's effect ===
- Root cause fixed: tool_selection_accuracy rose from 0.8889 -> 0.9556 (cars)
  and 0.8125 -> 0.9375 (real_estate). The specific known-failing cases
  (cars 37/38/40/41/42; real_estate 38-45) now call create_lead directly
  instead of searching again, in isolated re-checks (see the Task
  Completion Improvement report for the exact before/after per case).
- cars task_completion_rate improved: 0.8444 -> 0.8667 (an isolated
  full-suite run right after the first prompt version scored 0.9111; the
  reported 0.8667 is from the final committed prompt version and includes
  normal free-tier-LLM run-to-run variance, see the report for detail).
- real_estate task_completion_rate is flat at 0.7917 despite the large
  tool_selection improvement: newly-correct create_lead calls now expose a
  secondary, structural issue -- the eval's expected "name" field format
  differs by domain (cars: bare item name; real_estate: "<location>
  property, $<price>") in a way a domain-agnostic prompt cannot special-case
  without violating the "no domain-specific strings in agent_loop.py"
  constraint. This is a genuine remaining limitation, documented rather than
  papered over. See the full report for details and the specific cases
  involved.
